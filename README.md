# ChessBox（棋盒）

一个自托管的开源在线棋牌平台。在一台机器上启动服务后，玩家打开分享链接即可进入同一个房间对弈，无需注册、无需安装客户端。内置七种游戏：中国象棋、国际象棋、围棋、五子棋、中国跳棋、三国杀·自由混战、UNO。

所有对局由服务端权威裁决：客户端只提交操作（走子 / 出牌 / 响应），合法性判断、结果判定、随机数全部在服务端完成，任何客户端都无法伪造棋步、牌面或胜负。

## 游戏列表

### 中国象棋

- 双人对弈，服务端完整实现走势合法性（蹩马腿、塞象眼、将帅照面、困毙等）
- 点击棋子显示合法落点提示，走子 / 吃子 / 将军动画
- 悔棋（对方同意）、提和、认输、重新开局
- 中文纵线记谱导出 + 自定义 JSON 导出

### 国际象棋

- 双人对弈，完整规则含王车易位、吃过路兵、兵升变、逼和 / 超时判定
- PGN 与 FEN 导出，内置复盘走子记录

### 围棋

- 双人对弈，支持 9 / 13 / 19 路棋盘
- 提子、劫争（superko 禁着）、数目与点目结算
- 自由选座与让先设置

### 五子棋

- 双人对弈，连五即胜，可选禁手开关
- 悔棋、和棋判定

### 中国跳棋

- 2–6 人，标准十字星形 121 孔位棋盘，六色阵营
- 无强制跳跃、无吃子；普通移动、单跳、多段连跳均可，也可停一手
- 进入目标营区后不得离开；己方全部棋子到达目标营区获胜；双方连续停一手判和
- 自由选座：玩家在房间内自选六色阵营，目标为所选营地的对面营区，满员自动开局

### 三国杀·自由混战

- 3–4 人混战模式：无主公、无身份、无阵营，最后存活者获胜
- 27 名武将（2013 标准版）全部可用，技能由服务端结算；主公技在本模式自动禁用
- 160 张牌：标准版 108 张（含 4 张 EX）+ 军争篇 52 张，含延时锦囊、装备、铁索连环、拼点、濒死求桃等完整流程
- 回合流程：判定 → 摸牌 → 出牌 → 弃牌；无懈可击响应链、距离与攻击范围、装备栏全部服务端计算
- 玩家只能看到自己的手牌与公开信息，其余玩家的手牌与牌堆顺序不下发
- 超时托管：长时间未操作自动按默认策略行动，避免对局卡死

### UNO

- 3–4 人经典混战与 2v2 团队模式
- 三套牌组独立使用、绝不混洗：经典 108 张、经典扩展 112 张（含万能换手与自定义万能牌）、UNO Teams 112 张
- Teams 模式包含开局传牌、Team Play / Team Draw Four 团队万能牌、Passing Symbol 标记、出局与回归
- 万能牌选色、质疑 +4、UNO 喊报与惩罚均由服务端判定

## 平台功能

- **房间系统**：首页创建房间生成链接，任何人打开链接即加入；坐满自动开局，额外玩家进入观战；观战者不能干扰对局
- **断线重连**：刷新页面即恢复席位与局面；客户端以命令日志重放重建状态，服务端以版本号保证幂等
- **持久化**：对局状态写入 SQLite（WAL 模式），服务重启后房间可恢复继续
- **个性化广播**：同一房间的每个玩家收到各自视角的状态（手牌 / 暗牌不外泄）；服务端对下发视图做投影裁剪
- **延迟面板**：房间内实时显示 RTT 与网络抖动，帮助判断联机质量
- **动画与性能**：走子 / 出牌动画，提供流畅 / 精简 / 关闭三档性能模式，低端设备可降级
- **响应式布局**：320px 手机到宽屏桌面均无横向溢出，触屏可操作
- **输入防护**：所有 socket 命令经 schema 校验 + 游戏内深度校验双重闸门，并有限流防刷
- **无 eval、无动态执行**：全部逻辑为静态 TypeScript

## 技术栈

- 前端：React 19 + TypeScript + Vite，Socket.IO 客户端
- 后端：Node.js + Express 5 + Socket.IO 4，TypeScript
- 存储：better-sqlite3（WAL）
- 公网联机：cloudflared Quick Tunnel（可选，脚本一键启动；也可替换为任意反代方案）

## 运行

```bash
npm install
npm run build
npm start          # http://127.0.0.1:3001
```

开发模式（前端热更新）：

```bash
npm run dev        # 后端 127.0.0.1:3001，前端 5173
```

生成公网邀请链接（可选）：

```bash
npm run tunnel     # 未安装 cloudflared 时先执行 npm run tunnel -- --install
```

Quick Tunnel 的地址每次重启会变化，且隧道停止即失效；适合朋友间临时对弈，长期运行建议使用自有域名或固定隧道。

## 测试

```bash
npm test                # 单元 + 集成（Vitest）
npm run test:e2e        # 端到端（Playwright，需先 npm run build）
npm run typecheck       # 前后端类型检查
```

覆盖范围：棋类规则引擎单元测试（含穷举性质测试）、双模块卡牌游戏卡表 / 引擎 / 技能测试、真实 Socket.IO 多客户端集成测试（机器人打完整局）、浏览器端到端测试（建房—加入—对局—移动端溢出检查）。

## 已知限制

- 机器人在长时间高频连跑场景下，客户端累积广播状态可能内存增长；人类对局节奏（每次操作间隔秒级）不受影响，增量广播在计划中
- 卡牌游戏的牌面与武将为文字 / 原创图形实现，无官方美术素材与授权；对外运营前需自行处理商标与素材问题
- 服务端限流为单机内存实现，多进程部署需外置存储
