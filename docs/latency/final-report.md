# 五棋在线平台 · 全链路低延迟专项最终报告

- 报告时间：2026-11-05
- 代码基线：`055c452` + 本轮优化（未提交）
- 交付目录：`docs/latency/`
- 原始数据：`docs/latency/raw/*.json`
- 结论一句话：**服务端与数据库不是瓶颈（0.45–0.87 ms）；两秒延迟的主因是 Cloudflare Quick Tunnel 落地洛杉矶（WS P50 ≈0.46 s、抖动 1.2–1.5 s）与 polling 兜底（P50 2.81 s）。落子者自身可见延迟已用乐观 UI 降到 1–2 ms；对手可见延迟无法用前端代码消除，需改变部署路径。**

## A. 执行摘要

### A.1 用户问题与复现

- 用户反馈：朋友走完一步后约 2 秒才看到。
- 受控复现：
  - 强制 polling 经隧道：8/8 手 ack >2 s，P50 **2 805.9 ms**、P95 6 439.6 ms；对手可见 P50 1 322 ms。
  - 默认 WS 经隧道：P50 459 ms、P95 1 171 ms、最大 1 481 ms；无 >2 s。
- 结论：**「约两秒」可以稳定复现于 polling 路径；WS 路径是数百毫秒级。**

### A.2 根因排序

| 排序 | 根因 | 证据 | 影响 |
| ---: | --- | --- | --- |
| 1 | Cloudflare Quick Tunnel 落地 **LAX（洛杉矶）** | 日志 `location=lax01`；`CF-Ray ...-LAX`；TCP 建连 0.20–0.44 s、首字节 1.0–1.9 s | 所有实时交互基础 RTT 400 ms 起，抖动到 1.5 s |
| 2 | polling 兜底路径 | 强制 polling 8 手全部 >2 s，P50 2.81 s | WS 升级失败/被网络阻断时出现「两秒」 |
| 3 | 落子者无乐观 UI（本轮已修） | 旧客户端等 ack 才 setState；公网 ack ≈470 ms | 自己落子也慢；修复后 1–2 ms |
| 4 | 长局全量广播载荷 | 30 手 8.9 KB，线性增长 | 增加上行占用/丢包重传概率，非当前主因 |
| 5 | 快速点击触发 `STALE_REVISION` | 探针/ e2e 可触发；需重试 | 低概率，非延迟主因 |
| 6 | SQLite 同步写 | 0.17–0.61 ms | 亚毫秒，非主因；保留观察 |

## D. 根因定位（证据链）

1. **时间戳拆分**：ack 与服务端 total 的差值在网络；服务端 total 恒定 0.45–0.87 ms，网络从 0.3 ms（回环）到 459 ms（隧道），放大 1 500 倍。
2. **ack 与对手广播几乎同时**：同一手棋 ack 与对手 `room:state` 到达差 0–600 ms（抖动），不存在「广播额外延迟」。
3. **隧道落地**：`location=lax01` + `CF-Ray LAX`；curl TCP/TLS/TTFB 数据与 400 ms RTT 一致。
4. **polling 复现**：强制 polling 后单手 2.1–6.4 s，8/8 >2 s；与服务端无关（total 0.45 ms）。
5. **排除法**：本地 WS 0.79 ms、无定时器等待、无队列积压、无重复监听/连接、无串房、无规则重复计算、无 DB 慢查询、无锁等待。
6. **客户端缺口**：旧客户端等 ack 才更新棋盘；乐观 UI 后落子者 1–2 ms（隧道下同一次测试 ack 仍 472 ms）。

完整逐项清单见 `root-cause-report.md`（A-NET-001~012、B-SERVER-001~012、C-DB-001~008、D-FRONT-001~010、E-TUNNEL-001~008）。

## H. 安全与一致性回归

- 走棋服务端校验未改：座位→回合→revision→幂等→规则引擎；乐观 UI 只影响展示，失败回滚。
- `serverTiming` 只含数字，只随 ack 返回，不进入广播；`latency:ping` 无房间副作用；面板不含令牌/聊天。
- 请求 ID 幂等：同 ID 双发只落一子；旧 revision 被拒并返回最新状态；旧广播不覆盖新状态。
- 持久化失败回滚：避免「内存已走、DB 未落、客户端收到错误」的三方不一致（新增代码路径，未做故障注入）。
- 实时安全探测 9/9（敏感路径 404、CSP、nosniff、SAMEORIGIN、no-referrer、Permissions-Policy）。
- `npm audit --omit=dev`：0 vulnerabilities；`npm ls --depth=0` 无缺失/无效依赖。
- 控制台错误：layout/rwd/viewport/chk/ux/net-check 均为 0。
- 未做渗透测试/模糊测试/依赖供应链审计；未做真实故障注入。

### 总体判定：**PARTIAL**

- **代码与服务端质量：PASS**（亚毫秒处理、无丢步、无错误、乐观 UI 显著改善）。
- **公网对手延迟：FAIL/PARTIAL**，根因是部署路径（Cloudflare Quick Tunnel → 洛杉矶），不是本项目代码。
- 要彻底消除对手端 0.4–2 s：必须改变部署（国内节点/公网直连/IPv6/国内内网穿透）。这些需要用户授权与网络条件，本轮未执行。

### 发布建议

1. **可立即上线**当前代码：落子者体验已修复，服务端/规则/安全无回归。
2. 对手延迟按网络条件分级：
   - 同城/同网：预计数十毫秒（未实测）。
   - 跨省经当前隧道：0.4–1.5 s，属隧道物理成本。
   - 弱网/polling：2–6 s，看门狗会尝试回到 WS。
3. 若必须把跨省对手延迟压到 300 ms 内：优先「家庭公网 IPv4 端口映射」或「IPv6 直连」（免费，但需路由器/运营商支持）；其次国内节点内网穿透/轻量服务器（需授权与费用）。
