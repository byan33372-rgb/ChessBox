# 五棋升级 · 网络延迟报告（network-latency-report.md）

## 1. 通信架构（LAT-001~003/011）

- 全部实时事件走 Socket.IO 持久 WebSocket（websocket 优先、polling 回退），无逐步 HTTP。
- 广播仅发往 `io.to(roomId)`（房间隔离，LAT-011 ✅）；聊天与棋局事件分通道（LAT-006 ✅）。
- 走棋确认携带完整权威 RoomState（含 moves 全量）——LAT-004/005 指出的"仅发必要事件"未完全实现，为**已知权衡**（状态恢复简单可靠，消息体积随棋谱增长；长棋局优化列为后续项）。

## 2. 实测分段（LAT-013~019）

| 分段 | 场景 | 结果 |
|---|---|---|
| 用户输入→本地 UI 响应 | perf 输入延迟 60 样本 | P50=0.8ms / P95=1.5ms |
| 客户端→服务端确认→本端渲染（回环） | acceptance-perf 12 样本 | P50=12.8ms / P95=15.2ms |
| 点击→对端渲染（回环广播） | 同上 | P50=16ms / P95=28ms |
| 服务端 ack RTT（五棋 30min 浸泡） | 1424+ 样本/6min 轮；30min 逐周期 | P50=1–3ms / P95=2–3ms / P99=3–4ms / max≈5–10ms |
| 公网隧道（跨区） | 上一轮实测 | 边缘 6 国节点 200（0.73–1.07s 首包），WS 建立 ~2.7s 冷启 |

- RTT 分布按 LAT-019 报告 p50/p95/p99/max（soak-summary.json），超时比例 0（8s ack 超时无触发）。
- LAT-014 阶段语义：本地乐观反馈未实现（服务端确认驱动渲染，P95 回环 <20ms 可接受）；"服务端已确认"与"对端已渲染"由 room:state 广播顺序体现。

## 3. 服务端处理（LAT-007/009/020/022）

- 走棋路径：内存校验 + 单事务（moves+rooms）写 SQLite；engine 计算为 O(盘面)（围棋提子/数子均线性扫描），无阻塞任务。
- 并发：房间级 promise 队列串行化（NET-008）；多房间并行由 Node 事件循环承载——30 分钟浸泡 5 棋循环 + 双客户端并发 0 错误即为功能级并发证据；专用压测工具（多机并发）NOT_TESTED。

## 4. 环境差异（LAT-018/021）

- 回环与本机隧道已测；公网跨区 RTT 取决于家庭上行/隧道节点（上轮实测边缘首包 0.73–1.07s、WS 冷启 2.7s）——无法承诺固定毫秒数；若延迟不满意，方向为更换部署位置（如低成本云主机），未经授权不产生费用。

## 5. 一致性优先（LAT-023）

非法/过期/重复请求一律服务端拒绝（集成与浸泡 movesRejected 样本），未为降延迟放宽任何校验。
