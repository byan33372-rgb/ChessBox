## 1. 跳棋重大故障（第三阶段，用户专项）

### DEF-CK-001（P0）——已修复
- **现象**：用户报告"后三个棋子不能移动"；对局中若一方（尤其营内后三子被己方包围时）无可行着法，对局**永久死锁**。
- **根因证据**：探针 `/tmp/ck-e2.mjs`——a 营前缘清出后轮转正常；但引擎 `applyMove({from:'pass'})` 返回 null（`validatePath` 对 'pass' 直接判非法）→ 无停一手能力 → 无合法步且不能停 → 死锁。
- **根因**：跳棋引擎从未实现停一手（本轮 variant 声明含"无强制跳跃"，停一手是该变体的必要组成）。
- **修复**：引擎 pass 分支（轮转+连续计数）、连续两停判和、`passes` 写入 fen 并在 parseState 解析（重连恢复一致）、房间动作区新增「停一手」按钮。
- **回归**：checkers-phase3.test 12 项——停手轮转/双停判和/石子重置计数/fen 往返/被完全堵死场景（a:e1 + d:e2,f2,e3,g3 → 0 合法步 → 停一手破锁）/后三行逐步可达（交替行棋脚本）。

### DEF-CK-002（P1）——已修复
- **现象**：自由选座模式下部分阵营的合法营内步在 UI 上不显示/被误判非法。
- **根因**：客户端 `ckTargetCamp/ckOwnCamp` 仍用 `SEAT_CAMP_MAPS[n]`（固定人数映射），自由模式下 b..f 座位映射错误（如 2 人局 b 应为东北营1，被算成南营3）。
- **修复**：引擎暴露 `campOfSeat/targetOfSeat`（权威），Room 全部营地/目标计算改用引擎值。
- **回归**：DEF-CK-002 用例（2 人 b=营1、目标=营4；4 人 c=营2）。

### 附加发现（复审中顺带修复）
- 跳棋 `parseState` 未解析 `passes` → 重载后连续停一手计数丢失，可能二次死锁。已修复并由 fen 往返测试覆盖。

## 2. 棋盘拓扑穷举（用户专项要求）

121 孔位全量属性测试（checkers-phase3）：孔位数/六营各10/中心61、坐标↔内部节点双向映射（列字母+行号公式逐孔验证）、**邻接对称性**（a∈N(b)⇔b∈N(a) 全量）、**跳跃几何**（land=from+2×(mid−from) 全量）、像素坐标行列单调性（视觉映射无偏移）。结果：全部 PASS——不存在因索引/视觉坐标偏移而无法移动的孔位。

## 3. "后三个棋子"专项结论

- 满营时后三行（e1/e2/f2/e3/f3/g3）初始不可动属**规则正常**（被己方前缘堵住，且本变体无强制跳跃）；
- 修复后：前缘清空 → 后三行**逐步可达**（交替行棋脚本实证：e4→e5 后 e3→e4 → … → e1→e2，10/10 子全部动过）；
- 无合法步时**停一手**可用（P0 修复）；
- 死锁场景回归：尖子被堵 → 0 合法步 → 停一手 → 轮转继续。
